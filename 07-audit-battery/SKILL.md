# 07 审计质检（引导模式）

> 上线前最后一道关。4项检查，我带你一项一项做，每做完一项确认再继续。任何一项不通过都不能上线。

## 前置条件

- [ ] 本地测试全部通过（06完成）

## 这个阶段干什么

本地测试通过后，上线前做一次全面体检：
1. 安全审计 — 有没有漏洞、密钥泄露、注入风险
2. SEO审计 — 搜索引擎能不能搜到你
3. 性能审计 — 网站加载快不快
4. UX审计 — 用户用着顺不顺

---

## 第1步：安全审计（最重要）

**你做什么：** 把下面这段话发给AI，让它检查代码：

```
帮我做一次安全审计，逐项检查：

1. 密钥安全：
   - 前端代码里有没有硬编码的API Key（搜sk-开头的字符串）
   - .env文件有没有被Git忽略（检查.gitignore）
   - GitHub仓库是不是私有的
   - 后端接口有没有把密钥返回给前端

2. 注入防护：
   - 用户输入有没有做转义（防止XSS）
   - 后端接口有没有参数校验
   - 有没有SQL注入风险

3. 接口安全：
   - 后端接口有没有限流（防止被刷）
   - 错误信息会不会泄露系统细节（不要把堆栈trace返回给用户）
   - 上线后必须有HTTPS

4. 依赖安全：
   - 运行 npm audit，有没有已知漏洞
   - 有没有用已经停止维护的库

发现问题列出：文件路径、问题描述、修复建议。按严重程度排序。
```

**AI给出报告后，你做什么：**
- 高危问题立刻让AI修
- 中低危问题看情况修
- 修完后再让AI检查一遍

**安全审计通过了（无高危漏洞）告诉我，我带你做SEO审计。**

---

## 第2步：SEO审计

**你做什么：** 把下面这段话发给AI：

```
帮我做SEO优化：

1. 每个页面加独立的title（不超过60字）和meta description（不超过160字）
2. 检查HTML语义化：每页只有一个h1，h1→h2→h3层级正确
3. 所有图片加alt属性
4. 添加JSON-LD结构化数据（Organization/Product/FAQ）
5. URL结构清晰（用/xxx，不用?id=123）

产品是：（一句话描述你的产品）
目标关键词：（列3-5个）

只改SEO相关的代码，不要动其他功能。
```

**AI改完后你检查：**
- [ ] 每个页面title不一样，包含关键词
- [ ] 每个页面有meta description
- [ ] 每页只有一个h1
- [ ] 图片都有alt
- [ ] 有JSON-LD结构化数据

**SEO改完了告诉我，我带你做性能审计。**

---

## 第3步：性能审计

**你做什么：**

1. 打开Chrome，F12 → Lighthouse → 选「性能」和「SEO」→ 点「Analyze page load」
2. 等1-2分钟出报告
3. 看得分：
   - 性能 > 80 合格
   - SEO > 90 合格
   - 可访问性 > 90 合格

**如果得分不够，把下面这段话发给AI：**

```
帮我做性能优化，目标：首屏加载<3秒，Lighthouse性能得分>80。

当前问题：（把Lighthouse报告里的问题列出来，比如"图片未压缩""未使用的JavaScript""渲染阻塞资源"）

请：
1. 分析哪些地方加载慢
2. 图片压缩建议
3. 路由懒加载（首屏不加载所有页面）
4. 减少不必要的重渲染
5. 给出具体修改方案

只改性能相关代码，不要动功能。
```

**AI改完后重新跑一次Lighthouse，确认得分达标。**

**性能达标了告诉我，我带你做UX审计。**

---

## 第4步：UX审计

**你做什么：** 把下面这段话发给AI，或者找一个没用过你网站的人，让他用，你在旁边看：

```
从新用户视角评估这个网站，帮我做UX审查：

1. 新用户3秒内能看懂这是干什么的吗？
2. 核心功能（聊天/主要功能）几步能到达？（目标3步以内）
3. 有没有让用户困惑的地方？
4. 操作后有没有反馈？（loading/成功提示/错误提示）
5. 出错了有没有恢复路径？（不是死路）
6. 视觉一致性：所有页面配色、按钮样式、间距一致吗？
7. 可访问性：文字对比度够不够？键盘能不能操作？

给出具体改进建议，按优先级排序。不要泛泛而谈，要说清楚哪个页面、哪个元素、怎么改。
```

**AI给出建议后，你做什么：**
- 高优先级的问题立刻改
- 中低优先级看情况改
- 改完后再让一个新人用一遍，看他还会不会卡住

**UX改完了告诉我，我们做最终确认。**

## 避坑提示

1. **安全是底线** — 密钥泄露、被黑、数据泄露，这些问题比功能bug严重100倍
2. **SEO不是玄学** — title、description、语义化HTML、速度，这几个做好了就超过80%的网站
3. **性能差用户直接走** — 加载超过3秒，50%的用户会关掉，再也不回来
4. **UX问题自己看不出来** — 找个没用过的人，让他用，你在旁边看他在哪卡住，比AI分析100遍都管用
5. **审计发现问题不要怕** — 上线前发现是好事，上线后被用户发现才是灾难
6. **四项审计可以并行做** — 安全、SEO、性能、UX，开4个对话同时跑，省时间
7. **审计不是一次性的** — 每次大改后都要重新审计，特别是安全和性能
