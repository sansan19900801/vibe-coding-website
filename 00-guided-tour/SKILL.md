# 00 新手引导模式

> 输入 `/vibe新手入门` 触发。我当你的教练，一步一步带你做网站。每步只做一件事，你做完告诉我"好了"，我再带你做下一步。不用读任何文档，照着我说的做就行。

## 这个模式怎么用

你不需要懂技术，不需要看其他文档。我会：
1. 告诉你现在该做什么
2. 给你可以直接复制的prompt（复制给AI工具就行）
3. 告诉你怎么判断做好了
4. 你做好了告诉我，我再讲下一步

**全程9步，从0到上线。**

---

## 第1步：想清楚你的网站（品牌访谈）

**这一步你只需要做一件事：回答AI的问题，把你的想法说清楚。**

### 怎么做

打开豆包（或任何AI聊天工具），复制下面这段话发过去：

```
你现在是我的网站需求访谈员。我要做一个网站，请你用提问的方式帮我把需求理清楚。

规则：
1. 一次只问1-2个问题，不要一次问太多
2. 我回答后你再问下一个
3. 我说不清楚的，你给我几个选项让我挑
4. 全部问完后，帮我整理成一份品牌配置文档

开始吧，先问第一个问题。
```

然后AI会问你问题，你就用大白话回答。它会问这些方面：
- 网站是干什么的？解决谁的什么问题？
- 跟别人比有什么不一样？
- 用户打开网站第一件事想干什么？
- 你想要什么风格？（说不清就找个参考网站）
- 必须有的功能是什么？（3-5个，不要贪多）
- 网站叫什么名字？收费吗？

### 怎么判断做好了

AI最后会给你一份 `brand-config.md`，里面写清楚了：
- 产品一句话定位
- 目标用户是谁
- 核心功能有哪些
- 设计风格是什么
- 品牌名和收费模式

**拿到这份文档了，告诉我"第1步好了"，我带你做第2步。**

---

## 第2步：把需求变成功能清单（PRD）

**这一步你只需要做一件事：确认AI写的功能清单对不对。**

### 怎么做

把上一步的 `brand-config.md` 发给AI，再加这段话：

```
基于上面的品牌配置，帮我写一份PRD（产品需求文档）。

要求：
1. 列出所有页面，每个页面一句话说明用途
2. 每个页面有哪些功能，分"必须有"和"以后做"
3. 每个功能的验收标准要具体（比如"点击按钮弹出对话框"，不要说"功能正常"）
4. 用户从打开网站到完成核心动作的每一步
5. 明确列出"这个版本不做什么"

输出Markdown格式。
```

AI写完后你看一遍：
- 页面有没有漏掉你想要的？
- 功能是不是太多了？（MVP只留最核心的3-5个）
- 验收标准是不是具体可验证的？

有问题就跟AI说改，改到你满意。

### 怎么判断做好了

有一份 `PRD.md`，包含：
- 页面清单（不超过8个页面）
- 每个页面的功能+验收标准
- 用户核心流程
- 明确的"不做什么"列表

**确认好了，告诉我"第2步好了"，我带你做第3步。**

---

## 第3步：定设计风格（设计方案）

**这一步你只需要做一件事：定配色、找参考图、确认页面布局。**

### 怎么做

**先找参考图（最重要！）** 去网上找你觉得好看的同类型网站，截图保存。至少3张。

然后把PRD+参考图发给AI，加这段话：

```
基于PRD和参考图，帮我出设计方案：
1. 配色方案（给具体色值，比如#FF6B35）
2. 字体规范（标题/正文用多大）
3. 布局规范（间距/圆角/阴影）
4. 每个页面从上到下有什么模块（线框图描述）
5. 动效建议

色值必须给具体的十六进制代码，不要说"蓝色"这种模糊描述。
```

AI写完后你看：
- 配色是不是你想要的？
- 页面布局合不合理？
- 参考图的感觉有没有体现出来？

### 怎么判断做好了

有一份 `design-spec.md`，包含：
- 具体的配色色值（不是模糊描述）
- 字体/间距/圆角规范
- 每个页面的模块布局
- 至少3张参考图

**确认好了，告诉我"第3步好了"，我带你做第4步。**

---

## 第4步：让AI写网页代码（前端生成）

**这一步你只需要做一件事：一个页面一个页面地让AI写，写完一个你看一个。**

### 怎么做

打开CodeX（或其他AI编程工具），新建项目。

**先给AI定规矩（项目宪法），复制这段话：**

```
我要做一个AI网站，严格遵守以下规范：

【技术栈】React + TypeScript + Tailwind CSS
【设计规范】（把design-spec.md的配色/字体/布局粘贴在这里）
【规则】
1. 一次只做一个页面，做完等我确认再做下一个
2. 严格按设计规范的配色，不要自己改
3. 所有文字用真实内容，不要Lorem ipsum
4. 手机电脑都要适配
5. 大改前提醒我先保存

先初始化项目结构和路由，页面先做占位，等我确认再逐个实现。
```

**然后一个页面一个页面地做。** 每次跟AI说：

```
现在做【页面名】，功能：（从PRD复制该页面的功能）
验收标准：（从PRD复制验收标准）
布局：（从design-spec复制该页面的模块）
做完告诉我用了哪些组件，我来检查。
```

**每个页面AI写完后，你立刻检查：**
- 配色对不对？
- 按钮能不能点？
- 手机端正常吗？
- 有问题直接说具体的："这个按钮颜色改成#FF6B35"，不要说"优化一下"

改到满意再做下一个页面。

### 怎么判断做好了

- 所有页面都做完了
- 每个页面你都检查过，配色功能都对
- 手机端电脑端都正常
- 所有链接都能跳转，没有死链接

**全部页面做好了，告诉我"第4步好了"，我带你做第5步。**

---

## 第5步：对接AI大模型（后端生成）

**这一步你只需要做一件事：注册AI平台拿密钥，让AI写后端，测试聊天。**

### 怎么做

**1. 注册DeepSeek（最便宜好用）**
- 打开 https://platform.deepseek.com
- 注册+实名+充10块钱
- 进入「API Keys」→ 创建密钥 → 复制保存（只显示一次！）

**2. 让AI写后端，复制这段话：**

```
现在做后端，Node.js + Express：
1. POST /api/chat/stream — 接收用户消息，转发给DeepSeek，流式返回（打字机效果）
2. API Key从环境变量读，不要硬编码
3. 每个员工有不同的系统提示词，单独放文件
4. 简单限流：免费用户每天3次
5. 错误处理：AI调用失败返回友好提示

先初始化项目，然后逐个实现接口，做完一个我测一个。
```

**3. 配置密钥** 在后端项目的 `.env` 文件里填：
```
DEEPSEEK_API_KEY=你刚才复制的密钥
PORT=3001
```

**4. 测试接口** 用curl或浏览器测试能不能收到AI回复。

**5. 前后端联调** 让AI把前端聊天页跟后端连起来，实现打字机效果。

### ⚠️ 关键提醒

- 密钥绝对不能放到前端代码里（F12就能看到，会被盗刷）
- `.env` 文件不要上传到GitHub
- 先测后端接口，通了再跟前端连

### 怎么判断做好了

- 后端能启动
- 接口能返回AI回复
- 前端聊天页能真实聊天，打字机效果流畅
- 免费次数限制生效
- 网络断开有友好提示

**聊天功能正常了，告诉我"第5步好了"，我带你做第6步。**

## 第6步：自己电脑上测一遍（本地测试）

**这一步你只需要做一件事：从头到尾把网站用一遍，找出所有问题。**

### 怎么做

照着这个清单一项一项测：

**页面测试：**
- [ ] 每个页面都能打开，不白屏不404
- [ ] 没有乱码、没有占位文字
- [ ] 图片不裂图
- [ ] 布局不乱

**功能测试：**
- [ ] 导航每个菜单都能点
- [ ] AI聊天能正常回复，5秒内开始输出
- [ ] Markdown格式正确（代码/列表/加粗）
- [ ] 招聘/会员/支付等功能都正常
- [ ] 表单空内容不能提交

**手机测试（必须测！）：**
- [ ] 浏览器F12切手机模式，每个页面都看
- [ ] 按钮够大（能点到）
- [ ] 输入时键盘不挡内容

**异常测试（故意搞破坏）：**
- [ ] 断网后操作有提示
- [ ] 快速连点不重复提交
- [ ] 输入超长文字不崩
- [ ] F12 Console没有红色报错

**发现bug记下来，全部测完后一起让AI修：**
```
帮我修复以下bug，按优先级：
1. 【页面】问题描述
2. 【页面】问题描述
每个修完说明改了什么。
```

### 怎么判断做好了

- 清单全部打勾
- 所有bug修复并重新测过
- 你自己从头到尾用了一遍，感觉顺畅

**全部测通了，告诉我"第6步好了"，我带你做第7步。**

---

## 第7步：上线前体检（审计质检）

**这一步你只需要做一件事：让AI做4项检查，有问题就修。**

### 怎么做

让AI分别做这4项检查（可以开4个对话并行做）：

**1. 安全检查：**
```
帮我做安全审计：
1. 前端代码有没有硬编码的API Key（搜sk-开头）
2. 用户输入有没有XSS风险
3. 后端接口有没有限流
4. .env有没有被Git忽略
发现问题列出文件路径和修复建议。
```

**2. SEO检查：**
```
帮我做SEO优化：
1. 每个页面加title和meta description
2. 检查h1/h2标题层级
3. 图片加alt属性
4. 加JSON-LD结构化数据
产品是：（一句话描述）
关键词：（3-5个）
```

**3. 性能检查：**
```
帮我做性能优化：
1. 分析哪些地方加载慢
2. 图片压缩建议
3. 路由懒加载
目标：首屏加载<3秒
```

**4. UX检查：**
```
从新用户视角评估这个网站：
1. 3秒内能看懂这是干什么的吗
2. 核心功能几步能到
3. 有没有让人困惑的地方
4. 操作反馈充分吗
给出具体改进建议，按优先级排序。
```

有问题就让AI修，修完再测一遍。

### 怎么判断做好了

- 安全无高危漏洞
- API Key无泄露风险
- 每个页面有title和description
- 首屏加载<3秒
- 核心功能3步内到达
- 操作都有反馈

**体检通过了，告诉我"第7步好了"，我带你做第8步（部署上线）。**

## 第8步：买域名备案上线（国内部署）

**这一步需要你实际操作，我一步一步带你，每步确认完再继续。**

> 这一步涉及花钱和备案，我会一次只讲一步，你操作完告诉我，我再讲下一步。详细步骤见 [08-deploy-cn](./08-deploy-cn/SKILL.md)。

### 第8.1步：买云服务器

**做什么：** 买一台2核4G的云服务器（阿里云或腾讯云），拿到公网IP。

**怎么做：**
1. 打开阿里云或腾讯云
2. 搜「云服务器ECS」
3. 选2核4G、CentOS 7.9、3M带宽、按年付费
4. 设置root密码，付款
5. 控制台找到服务器，复制公网IP

**⚠️ 注意：** 选「云服务器ECS」，不要选「轻量应用服务器」。

**买好了，把服务器IP发给我，我带你做下一步。**

### 第8.2步：买域名+实名

**做什么：** 买一个.com域名，完成个体户实名认证。

**怎么做：**
1. 在同一个平台（阿里云/腾讯云）买.com域名
2. 进入域名管理 → 实名认证 → 选「个体工商户」
3. 上传营业执照+身份证，填地址（跟执照完全一致），刷脸
4. 等1-2天审核通过

**⚠️ 注意：** 域名持有者名称必须跟营业执照完全一致，一个字都不能差。

**实名通过了告诉我，我带你做下一步。**

### 第8.3步：ICP备案

**做什么：** 提交备案，等7-14天审核。

**怎么做：**
1. 服务器平台找到「ICP备案」入口
2. 网站名填「XXAI工具服务平台」（不要填测试/demo，不要带中国/全国/官方）
3. 上传材料，刷脸，提交
4. 等审核（期间继续优化网站，不要干等）

**备案通过了，把备案号发给我，我带你做下一步。**

### 第8.4步：装宝塔面板

**做什么：** 给服务器装可视化管理面板。

**怎么做：**
1. SSH连接服务器：`ssh root@你的IP`
2. 复制安装命令执行（CentOS/Ubuntu命令不同，见08-deploy-cn）
3. 等3-5分钟，保存好宝塔登录地址+账号+密码
4. 登录宝塔，装Nginx + PM2管理器

**宝塔装好了告诉我，我带你做下一步。**

### 第8.5步：上传代码

**做什么：** 把前端和后端代码传到服务器。

**怎么做：**
1. 前端 `npm run build` 打包，dist文件上传到 `/www/wwwroot/你的域名/`
2. 后端代码上传到 `/www/server/你的项目/`
3. 后端配 `.env`（填真实API Key）
4. PM2添加项目，启动后端

**代码上传好了告诉我，我带你做下一步。**

### 第8.6步：域名解析+绑定+HTTPS

**做什么：** 让域名指向服务器，装安全证书。

**怎么做：**
1. 域名平台加两条解析：@和www都指向服务器IP
2. 宝塔添加站点，绑定域名
3. 宝塔→SSL→Let's Encrypt申请证书→开启强制HTTPS
4. 网站底部挂备案号

**全部弄好了，电脑手机都测一遍能正常访问，告诉我"第8步好了"。**

## 第9步：上线后维护（持续运营）

**网站上线不是结束，是开始。这一步教你怎么长期维护。**

### 日常做什么

**每周检查一次：**
- [ ] 网站能正常打开
- [ ] AI聊天正常
- [ ] 服务器CPU/内存不超过80%
- [ ] 域名和证书没过期
- [ ] 看用户反馈，有没有bug

**加新功能：**
1. 想清楚要加什么，写进PRD
2. 让AI做（一次只做一个功能）
3. 本地测完再上线
4. 上线后观察有没有问题

**修bug：**
1. 用户反馈问题 → 自己复现
2. 把报错信息发给AI
3. AI修复 → 本地测试 → 上线

**换AI模型：**
- 想换DeepSeek/千问/GLM，只改后端 `.env` 里的密钥和模型名
- 不用改网站，不用换服务器

**备份：**
- 代码推送到GitHub（私有仓库）
- 宝塔设置自动备份（每天一次）

---

## 引导模式的规则

1. **一次只讲一步**，用户确认完成再讲下一步
2. **每步只做一件事**，不跳步
3. **给可直接复制的prompt**，用户不用自己想怎么说
4. **用大白话**，不用技术术语，必须用的术语立刻解释
5. **用户说"卡住了"就给更详细的操作**，用户说"懂了"就继续
6. **每步结束问用户"做好了吗？"**，等用户确认再继续
