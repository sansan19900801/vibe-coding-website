# 05 后端生成（引导模式）

> 前端是"样子货"，后端才是"大脑"。我一步一步带你，先拿API密钥，再一个接口一个接口地做，测通一个再继续。

## 前置条件

- [ ] 前端页面全部做完（04完成）
- [ ] 有一张能充值的银行卡/支付宝（AI平台充值用，10块钱够测很久）

## 这个阶段干什么

1. 注册AI大模型平台，拿到API密钥
2. 让AI写后端程序，负责把用户提问转发给大模型，把回答返回给前端
3. 一个接口一个接口地测试
4. 前后端联调，让网站能真实聊天

---

## 第1步：注册AI平台，拿API密钥

**你做什么：**

1. 打开 https://platform.deepseek.com （推荐，最便宜，中文最好）
2. 注册账号，实名认证
3. 充值10块钱（够用很久，测试期花不完）
4. 进入「API Keys」页面
5. 点「创建新的密钥」，名字随便填
6. 复制密钥，保存到一个安全的地方

**⚠️ 极其重要：**
- 这个密钥**只显示一次**，关掉就看不到了，必须立刻复制保存
- 这个密钥**绝对不能**放到前端代码里（F12就能看到，会被盗刷你的钱）
- 密钥丢了立刻去平台删掉重建

**拿到密钥了告诉我，我带你做下一步。**

---

## 第2步：初始化后端项目

**你做什么：** 在CodeX里，复制下面这段话发给AI：

```
现在做后端，技术栈和要求：

【技术栈】
Node.js + Express + cors + dotenv + axios

【功能需求】
1. POST /api/chat — 接收用户消息，转发给DeepSeek，返回AI回复
2. POST /api/chat/stream — SSE流式输出（打字机效果）
3. GET /api/user/status — 返回用户剩余次数/会员状态
4. 简单限流：免费用户每天3次，会员不限

【AI对接要求】
1. DeepSeek的API Key从环境变量读取（process.env.DEEPSEEK_API_KEY）
2. 预留模型切换配置，以后换千问/GPT只改配置
3. 系统提示词（system prompt）单独放一个文件，方便修改
4. 错误处理：AI调用失败时返回友好提示，不要崩

【项目结构】
server/
├── index.js          # 入口
├── .env              # 环境变量（API Key，不要提交Git）
├── routes/
│   └── chat.js       # 聊天接口
├── services/
│   └── ai.js         # AI对接服务（可切换模型）
├── middleware/
│   └── rateLimit.js  # 限流
└── prompts/          # 每个员工的系统提示词
    └── default.md

先初始化项目，安装依赖，创建项目结构。
.env文件里先留空，我等下填入真实密钥。
```

**AI做完后你检查：**
- 项目结构对不对？
- 依赖装好了吗？
- `.env` 文件创建了吗？`.gitignore` 里有没有忽略 `.env`？

**确认初始化好了，告诉我，我带你配置密钥。**

## 第3步：配置API密钥

**你做什么：**

1. 打开后端项目的 `.env` 文件
2. 填入：
   ```
   DEEPSEEK_API_KEY=你刚才复制的密钥
   PORT=3001
   ```
3. 保存

**⚠️ 检查：**
- `.gitignore` 文件里有没有 `.env`？没有的话加上，防止密钥被提交到GitHub
- 前端代码里搜一下有没有 `sk-` 开头的字符串（绝对不能有）

**密钥配置好了告诉我，我带你做第一个接口。**

---

## 第4步：做第一个接口（普通聊天）

**你做什么：** 跟AI说：

```
现在做 POST /api/chat 接口：
1. 接收参数：message（用户消息）、employeeId（员工ID，可选）、userId（用户ID）
2. 根据employeeId读取对应的系统提示词
3. 调用DeepSeek API，把消息+系统提示词发过去
4. 返回AI的回复
5. 错误处理：网络错误/API报错时返回 {error: "AI暂时不可用，请稍后重试"}
6. 限流：免费用户每天最多3次（用userId识别，存在内存里就行）

做完后告诉我怎么测试，我来测。
```

**AI做完后你测试：**
```bash
# 启动后端
cd server && npm start

# 另开一个终端，测试接口
curl -X POST http://localhost:3001/api/chat \
  -H "Content-Type: application/json" \
  -d '{"message":"你好","userId":"test123"}'
```

能收到AI回复 → 接口通了 → 继续下一个接口。
收不到 → 把报错发给AI，让它修。

**普通聊天接口测通了告诉我，我带你做流式输出。**

## 第5步：做流式输出接口（打字机效果）

**你做什么：** 跟AI说：

```
现在做 POST /api/chat/stream 接口，用SSE（Server-Sent Events）实现流式输出：
1. 接收参数跟普通聊天一样
2. 调用DeepSeek的流式API（stream: true）
3. 把AI返回的chunk逐字转发给前端
4. 结束时发送 [DONE] 标记
5. 错误处理：中途出错也要关闭连接，返回错误信息

做完后告诉我怎么测试。
```

**测试方法：** 用浏览器或curl测试，能看到数据一段一段地回来，就是流式输出。

**流式接口测通了告诉我，我带你做前后端联调。**

## 第6步：前后端联调

**你做什么：** 跟AI说：

```
现在把前端聊天页跟后端联调：
1. 前端发送按钮调用 /api/chat/stream 接口
2. 用EventSource或fetch接收SSE流式数据
3. 实现打字机效果，逐字显示AI回复
4. 根据employeeId传不同的员工人设
5. 错误处理：后端返回错误时显示友好提示
6. 开发环境前端代理到 http://localhost:3001
7. 发送时按钮变loading，不能重复提交

只改聊天页相关代码，不要动其他页面。
```

**联调完后你在浏览器里真实测：**
- 输入问题，能收到回复吗？
- 打字机效果流畅吗？
- 5秒内开始输出了吗？
- Markdown格式（代码/列表/加粗）渲染正确吗？
- 网络断开时有提示吗？
- 免费次数限制生效吗？

**全部正常，告诉我"第5步完成"，我带你做第6步（本地测试）。**

## 避坑提示

1. **API Key绝对不能放前端** — 任何人F12看源码就能偷走，盗刷你的钱。必须只放后端环境变量
2. **先测后端再联调** — 后端接口用curl测通了，再跟前端连，不然出了问题不知道是前端还是后端的锅
3. **流式输出比一次性返回体验好10倍** — 用户等5秒才看到完整回复会焦虑，流式输出一开始打字就感觉很快
4. **系统提示词很重要** — AI的回答质量取决于你给它的角色设定，花时间打磨prompts/里的文件
5. **一定要有限流** — 不做限流，有人恶意刷接口，你的AI费用会爆炸
6. **错误处理不能省** — AI偶尔会返回错误或超时，前端必须有提示，不能白屏
7. **换AI模型只改配置** — 代码结构要设计成"换模型只改一个文件"，不要把DeepSeek的逻辑写死在各处
