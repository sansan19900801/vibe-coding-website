# 09 持续维护（引导模式）

> 网站上线不是结束，是开始。我按场景带你做日常维护，遇到什么问题就走对应的流程。

## 这个阶段干什么

网站上线后的日常运营：
- 修bug（用户反馈的问题）
- 加新功能（根据用户需求）
- 换AI模型（哪个好用用哪个）
- 监控稳定性（网站挂了能知道）
- 备份数据（防止丢数据）
- 优化性能（用户多了不卡）

---

## 场景1：用户反馈有bug

**第1步：确认bug**

用户说"网站有问题"，不要慌，先问清楚：
1. 在哪个页面？
2. 做了什么操作？
3. 出现了什么问题？（最好要截图或录屏）
4. 用的什么设备？（手机/电脑，什么浏览器）

**第2步：自己复现**
- 按照用户说的步骤操作一遍
- 能复现 → 能修
- 不能复现 → 让用户提供更多信息（录屏最好）

**第3步：定位原因**
- F12打开Console，看有没有红色报错
- F12打开Network，看有没有请求失败
- 后端日志有没有报错
- 把报错信息复制下来

**第4步：让AI修复**

```
帮我修复一个bug：

【现象】（用户看到了什么）
【复现步骤】（怎么操作能出现）
【报错信息】（F12 Console的报错，或后端日志）
【预期行为】（应该是什么样）

帮我定位原因并修复，只改相关代码，不要动其他地方。
修复后说明：改了哪个文件、为什么这么改。
```

**第5步：本地测试**
- 修复后在本地测一遍
- 确认bug修好了
- 确认没有引入新bug（回归测试）

**第6步：部署上线**
- 前端重新build，上传到服务器
- 后端PM2重启
- 线上再测一遍

---

## 场景2：想加新功能

**第1步：想清楚需求**
- 这个功能解决什么问题？
- 给谁用？
- 有了之后用户体验有什么提升？

**第2步：写进PRD**
更新PRD.md，加功能描述和验收标准。

**第3步：更新设计（如果涉及UI）**
更新design-spec.md，说明新功能长什么样。

**第4步：让AI做（一次只做一个功能）**

```
我要加一个新功能：【功能名】

【需求】（这个功能干什么，解决什么问题）
【验收标准】（做成什么样算合格，要具体）
【设计要求】（如果涉及UI，描述样式）
【位置】（在哪个页面加，跟现有功能什么关系）

请先给我实现方案，等我确认后再写代码。
一次只做这一个功能，不要动其他地方。
```

**第5步：本地测试 → 部署上线**（同场景1的第5-6步）

## 场景3：想换AI模型

> 你的服务器不绑定任何AI，想换哪个换哪个，只改配置。

**支持的主流模型：**

| 模型 | 平台 | 特点 |
|------|------|------|
| DeepSeek-V3 | DeepSeek | 便宜、中文好、推理强 |
| Qwen-Max | 阿里千问 | 阿里生态、长文本 |
| GLM-4 | 智谱 | 国产、稳定 |
| GPT-4o | OpenAI | 最强、最贵、需翻墙 |
| Claude 3.5 | Anthropic | 写作强、需翻墙 |

**换模型步骤：**

1. 去对应平台注册账号、充值、拿到API Key
2. 修改后端 `.env` 文件：
   ```
   AI_PROVIDER=deepseek  # 改成 qwen / glm / openai
   AI_API_KEY=新的密钥
   AI_MODEL=模型名称
   ```
3. 如果后端代码写死了DeepSeek的API格式，让AI改成可切换的：
   ```
   帮我把AI对接改成可配置的，支持DeepSeek/千问/智谱/GPT切换。
   要求：只改services/ai.js，通过环境变量切换模型，API格式自动适配。
   ```
4. PM2重启后端服务
5. 测试聊天正常

**不确定哪个模型好？** 同时接几个，让用户在页面上选：
```
帮我加一个模型切换功能：
1. 聊天页右上角加下拉菜单，可选DeepSeek/千问/GLM
2. 用户选择后存在本地
3. 发送消息时带上用户选的模型
4. 后端根据模型参数调用对应API
```

## 场景4：网站打不开了/挂了

**第1步：确认是哪里的问题**
- 你自己打不开？还是用户说打不开？
- 是所有页面都打不开，还是某个功能不行？
- 手机和电脑都试一下

**第2步：检查服务器**
- 登录宝塔面板，看服务器是不是运行中
- 看CPU/内存/磁盘是不是满了
- 看Nginx是不是运行中
- 看PM2里后端是不是在线

**第3步：常见问题快速排查**

| 问题 | 可能原因 | 解决 |
|------|---------|------|
| 完全打不开 | 服务器挂了/欠费 | 续费/重启服务器 |
| 502错误 | 后端服务挂了 | PM2里重启后端 |
| 404 | 域名解析错了/站点配置错了 | 检查解析和宝塔站点 |
| 聊天没反应 | API Key过期/欠费 | 检查AI平台余额 |
| 加载很慢 | 服务器资源不够/图片太大 | 升级配置/压缩图片 |
| HTTPS报错 | 证书过期了 | 宝塔重新申请证书 |

**第4步：自己搞不定，把报错信息发给AI**
```
网站出问题了：
【现象】（具体描述）
【报错信息】（浏览器显示的错误，或宝塔日志）
【我做了什么】（最近改了什么）
帮我排查原因并给出修复步骤。
```

## 场景5：日常检查（每周一次）

照着这个清单每周检查一次：

- [ ] 网站能正常打开（电脑和手机都试）
- [ ] AI聊天功能正常
- [ ] 服务器CPU/内存不超过80%（宝塔面板看）
- [ ] 磁盘空间不超过90%
- [ ] 域名没过期（提前续费）
- [ ] HTTPS证书没过期
- [ ] AI平台余额够用
- [ ] 看一下用户反馈/评论，有没有bug
- [ ] 代码推送到GitHub备份了

## 场景6：数据备份

**备份什么：**
- 代码 → Git推送到GitHub（私有仓库）
- 数据库 → 宝塔设置自动备份（每天一次，保留7天）
- 用户上传的文件 → 打包下载
- 配置文件（.env、nginx配置）→ 下载到本地

**宝塔自动备份设置：**
1. 宝塔 → 计划任务
2. 添加任务：备份网站
3. 执行周期：每天凌晨3点
4. 备份到：本地 + 阿里云OSS（可选）

## 场景7：用户多了网站卡

**常见性能问题及解决：**

| 问题 | 原因 | 解决 |
|------|------|------|
| 加载慢 | 图片太大/代码没压缩 | 压缩图片、开启gzip、CDN加速 |
| AI回复慢 | 模型响应慢/网络差 | 换更快的模型、加超时重试 |
| 服务器卡 | CPU/内存不够 | 升级服务器配置、优化代码 |
| 并发高了崩 | 没做负载均衡 | 加服务器、用Redis缓存 |
| 数据库慢 | 查询没索引 | 加索引、优化SQL |

**让AI帮你优化：**
```
网站最近变慢了，帮我做性能优化：
1. 分析前端加载慢的原因（看Network面板）
2. 分析后端响应慢的原因（看接口耗时）
3. 给出具体优化方案
4. 按优先级逐个优化

当前服务器配置：（比如2核4G）
当前日活：（大概多少人）
主要慢在：（描述哪个操作慢）
```

- [ ] 网站正常运行，无报错
- [ ] AI聊天功能正常
- [ ] 服务器资源正常（CPU/内存/磁盘）

## 避坑提示

1. **上线后改代码必须先本地测** — 不要直接在服务器上改，改崩了用户立刻受影响
2. **每次上线前备份** — 万一新版本有问题，能快速回滚到旧版本
3. **换模型先测试再切** — 新模型可能回答质量差，先小范围测试
4. **不要频繁大改** — 一次改太多，出了问题不知道是哪改的
5. **监控比你想象的重要** — 网站挂了用户不会告诉你，他们直接走了
6. **数据丢了找不回来** — 备份是最低成本的保险，一定要做
7. **用户反馈是金矿** — 用户说的问题就是你要改的方向，认真对待每一条
8. **小步快跑迭代** — 不要等"完美"才上线，先上线再根据用户反馈慢慢优化
