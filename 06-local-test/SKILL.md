# 06 本地测试（引导模式）

> 铁律：本地没测好，绝不花钱买服务器、绝不备案。我带你一项一项测，每类测完确认再继续。

## 前置条件

- [ ] 前端全部页面做完（04完成）
- [ ] 后端接口全部写完，前后端联调完成（05完成）

## 这个阶段干什么

在自己电脑上，把网站从头到尾测一遍，找出所有问题。不要发现一个改一个，全部测完后统一修。

---

## 第1步：页面测试（每个页面都测）

**你做什么：** 打开网站，一个页面一个页面地看，每项打勾：

| 测试项 | 怎么测 | 通过标准 |
|--------|--------|---------|
| 页面能打开 | 点导航/输路由跳转 | 不白屏、不404 |
| 文字显示正常 | 看所有文字 | 没有乱码、没有占位符、没有英文Lorem |
| 图片显示正常 | 看所有图片 | 不裂图、不加载失败 |
| 布局不乱 | 看整体排版 | 没有错位、重叠、溢出 |
| 滚动流畅 | 上下滚动 | 不卡顿、没有跳动 |
| 刷新不丢数据 | F5刷新 | 对话历史/用户状态不丢失 |

**发现问题记下来：**
```
Bug清单：
1. 【页面名】问题描述
2. 【页面名】问题描述
```

**所有页面都测完了告诉我，我带你测功能。**

```

1. 【页面名】bug现象（比如"点击XX按钮后页面空白"）

【中优先级】
3. 【页面名】bug现象

【低优先级】
```

**AI修完后，你必须重新测一遍所有功能**（回归测试），防止修了A坏了B。

## 避坑提示

1. **不要只测"正常路径"** — 正常操作当然没问题，要故意搞破坏（断网、乱输入、快速点击），这些才是用户真实会遇到的
2. **手机端一定要测** — 80%的用户用手机打开，手机端出问题等于白做
3. **Console报错一个都不能留** — F12打开Console，红色报错全部解决，黄色警告尽量解决
4. **测试要自己亲手点** — 不要听AI说"测试通过了"，它说的不算，你自己点了才算
5. **bug要描述清楚** — 不要说"聊天有问题"，要说"在聊天页输入'你好'后，等了10秒没回复，Console显示404错误"
6. **修复后必须回归测试** — 修了一个bug可能引入新bug，全部重测一遍才放心
7. **性能差就是bug** — 加载慢、卡顿、动画不流畅，这些跟功能bug一样要修
